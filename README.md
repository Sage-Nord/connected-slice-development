# Connected Slice Development

**The strongest practical default for AI-driven engineering teams.**

Build one small, host-visible behavior at a time. Iterate quickly on an independently buildable core **when it has a real boundary**, but connect it to the production host early. The aim is the shortest path to a trustworthy answer, not merely a fast package build.

This works for new projects, features, changes, bug fixes, and business tickets. It favors typed contracts and focused tests without assuming types can invent business rules or that a long speculative spec must precede every change. Host-only work stays in the host; an existing capability reuses its unit. Real host checks and required platform/release gates still matter.
